\## Шаг 2. Разбор команд сравнения и поиска

\* Разница между `git diff`, `git show` и `git log`:

\* `git log` — выводит общую историю коммитов (автор, дата, хэши и сообщения).

\* `git diff` — показывает разницу (добавленные и удаленные строки) между конкретными состояниями файлов или коммитов.

\* `git show` — детально отображает метаданные и изменения (diff) только одного конкретного коммита.

\* Команда `git log -S"def"` нашла коммиты, в которых ключевое слово `"def"` было добавлено или удалено из кода.

\* Команда `git blame` показала файл построчно с указанием автора, даты и хэша коммита для каждого изменения.



\## Шаг 3. Восстановление файлов

\* `git restore <файл>` отменяет все незакоммиченные локальные правки в рабочей директории, возвращая файл к состоянию последнего коммита (`HEAD`).

\* `git restore --source=<коммит> <файл>` извлекает версию файла из указанного старого коммита и заменяет ею текущую рабочую копию.

\* Если бы у меня были важные незакоммиченные правки, обычный `git restore` безвозвратно стёр бы их.



## Шаг 5. Теги и ветки
* Тег — это статичная (постоянная) метка, привязанная к конкретному коммиту (например, для фиксации версий релиза). Она не двигается при создании новых коммитов.
* Ветка — это динамический (подвижный) указатель, который автоматически сдвигается вперед с каждым новым коммитом.
